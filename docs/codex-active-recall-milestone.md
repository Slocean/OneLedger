# Codex 主动召回：首个可交付里程碑

状态：待实施。基线日期：2026-09-29。

## 目标

Codex 在 OneLedger 仓库开始一项涉及项目的任务时，先通过现有 OneLedger MCP 调用 `memory.get`，读取 `scopeKind=project`、`scopeId=OneLedger` 的正式记忆。读取成功后再决定是否还需要全局记忆或关键词搜索。同一任务不重复读取相同作用域；没有命中时正常继续。

这个里程碑只解决 **Agent 会不会主动读、能否读对项目、读到后能否使用**。历史 inbox 整理、自动蒸馏、跨客户端接入和数据库迁移另行实施。现有 `global / project / personal` 作用域和整篇覆盖语义保持不变。

## 已核实的基线

- 运行中的 Tauri 便携版为上一版本（0.4.14 的前一版）；正式记忆 14 条，待蒸馏材料 137,490 条；`distill.provider=none`。这些待处理材料不能被当作 Agent 已可召回的正式记忆。
- 当前 Codex 会话已暴露 `memory.get` 等 5 个 OneLedger stdio MCP 工具。实际调用 `memory.get({scopeKind:"project",scopeId:"OneLedger"})` 返回 `[]`，说明连接可用，但此作用域目前没有正式记忆。
- Tauri HTTP MCP 的 `initialize` 返回使用说明，并可在客户端显式传入 `projectScopeId` 时附带项目索引；通用客户端是否传这个非标准字段不可依赖。当前试点直接在工具参数里传仓库名。
- 官方 [Codex MCP 文档](https://learn.chatgpt.com/docs/extend/mcp)说明 Codex 会读取 MCP 初始化的 `instructions`，并支持通过 `AGENTS.md` 引导工具使用。它没有承诺每项项目任务都会自动调用某个工具，因此必须做新任务实测。

## 实施路径

### 1. 固定项目识别与调用规则

在仓库根目录的 `AGENTS.md` 增加一段短规则，建议正文如下。放在项目硬规则之后，并确保不覆盖现有安全限制：

> 在 OneLedger 仓库处理项目任务时，开始检查或修改前，若 OneLedger MCP 可用，调用一次 `memory.get`，参数为 `scopeKind=project`、`scopeId=OneLedger`。项目名固定使用仓库名，不使用工作目录、相对路径或 worktree 目录名。返回空数组时继续任务，不把 inbox 当成正式记忆。只有任务需要跨项目偏好时再读取 `global`。同一任务已读取过且记忆未变化时不重复调用。工具不可用时继续完成能独立完成的工作，并在结论中说明未读取到记忆。

本试点使用已连接的 stdio MCP，不新增桌面壳或常驻服务。实施者先检查当前 Codex 配置和工具清单，复用可用连接；若连接缺失，由实施 Agent 自己配置和调用，不要求用户复制 MCP JSON、Bearer 或手工启动服务。密钥不得写入仓库、日志或测试文档。

### 2. 建立可观测的验收样本

先在只读状态下记录 `project:OneLedger` 的现有 `rev` 和记忆内容。当前基线为空；若实施时已有正式记忆，不覆盖它。

为验证“读到了以后会使用”，由实施 Agent 准备一篇经过安全扫描、内容真实、可长期保留的 OneLedger 项目记忆；写入前再次读取当前 `rev`，通过 `memory.remember` 提交整篇正文及 `expectedRev`。测试点必须是这篇记忆里的明确约定，并且测试任务提示不能提到 OneLedger、MCP、记忆或该约定。若没有合适的真实约定，使用隔离的测试账本和测试仓库；不要把随机暗号写进正式账本。

用现有审计里的 `memory.get` 事件确认调用发生，并查看 Agent 工具调用记录确认参数、顺序和返回值。审计只能证明工具被调用，不能证明 Agent 正确使用了内容，后者要检查实际答复或改动。

### 3. 新任务验收

实施 Agent 在新的 Codex 任务里执行以下场景，任务提示均不提醒它使用记忆：

1. **普通仓库任务**：在任何文件修改前调用一次 `memory.get(project, OneLedger)`；结果为空也不阻塞任务。
2. **有用记忆任务**：取回试点记忆，并在决策中使用其中一条相关约定；不能只调用工具却忽略内容。
3. **无关任务**：仍正确识别项目，但不把无关记忆硬套进回答或代码。
4. **worktree 任务**：工作目录名称与仓库名不同时，`scopeId` 仍为 `OneLedger`；不运行 `git.exe` 来猜仓库名。
5. **连接不可用**：任务继续，结论准确说明未读取记忆，不编造已召回的内容。

每个场景记录：任务标识、MCP 是否出现、调用参数、调用时点、返回条数、是否正确使用、耗时及失败原因。记录中只保留记忆 ID 和必要的短摘要，不复制敏感正文或密钥。至少再重复 5 个全新普通仓库任务，检查行为是否稳定，而非只凭一次成功。

### 4. 根据失败位置修复

- **工具未出现**：检查 Codex 当前主机的 MCP 连接和工具启用状态。若使用桌面 HTTP MCP，先实测 Codex 能否完成 `initialize`、`tools/list`、`memory.get`；当前 Rust HTTP 端点由手写 JSON-RPC 处理，不能仅凭普通 HTTP POST 成功就认定与 Codex 传输兼容。
- **工具出现但未主动调用**：先缩短和明确 `AGENTS.md` 规则，检查它是否进入新任务上下文；再检查 MCP `instructions` 的首 512 字符是否独立表达调用规则。不要靠反复扩写提示词掩盖不稳定结果。
- **项目名错误**：本仓库固定使用 `OneLedger`；跨仓库推广时再设计明确的仓库名映射。服务端工作目录和文件相对路径都不能作为 `scopeId`。
- **调用成功但使用错误**：检查样本是否与任务相关、记忆是否过期，并让 Agent 在实际改动中引用相应约定；不自动把原始 inbox 暴露给 Agent。
- **耗时明显过长**：分别测冷启动与连续调用。当前会话中一次冷调用约 20 秒、一次连续调用约 4 秒，仅作为待复核样本；若新任务的召回持续拖慢工作流，再定位 MCP 启动或传输开销。

## 完成标准

- 5 个规定场景全部通过；另 5 个全新普通仓库任务均在项目工作前正确读取 `project:OneLedger`，没有路径型或其他仓库的 `scopeId`。
- 有用记忆场景能证明内容影响了正确决策；无关场景不误用；空结果和连接故障均不编造记忆。
- 不向 Agent 开放 inbox、蒸馏草稿、secret/pii 或已存凭据原值；不把 MCP 密钥写入仓库。
- `npm run check` 通过；若改 Rust，再跑 `cargo test --offline --lib`。涉及 HTTP MCP 时，还需从打包的 Tauri 窗口实际完成 Codex 连接与 `memory.get`，并等待 Linux `check`、Windows `CI` 通过后才发版。
- 如果只是调整 `AGENTS.md` 且试点达标，可先作为仓库级行为交付；发版仍按项目的六处版本号和公告规则执行。

## 交付物与回退

实施交付包括：`AGENTS.md` 的最小召回规则、验收记录、必要的 MCP 兼容修复及对应测试。若试点记忆写入正式账本，记录其 ID、rev 和来源；撤销试点时按现有 `memory.forget` 流程处理，不直接改数据库。

若 5 个新任务仍不能稳定触发召回，移除新增的仓库规则，保留诊断记录；下一里程碑再评估客户端支持的事件入口或专用适配层。不要把“工具可手动调用”记为主动召回已完成。
