## 直接交给 ZCode 的指令

请在 `E:\Project\OneLedger` **直接实施并验收**本文，不要只复述方案。先遵守根目录 `AGENTS.md`，取得 `project:OneLedger` 正式记忆，再核实现有代码、当前数据库统计和工作区改动。保留其他人已有的未提交修改。交付代码、数据库迁移、Tauri 管理台操作界面、必要测试、真实窗口验收记录；自己调用 MCP 验证，不把连接配置或 Bearer 交给用户操作。

本任务的重点是把历史待蒸馏材料安全地归到正确项目，并让管理员**明确选择、审核、确认**要写入正式记忆的材料。不要对用户正在使用的 13 万余条材料自动批量迁移、自动删除或自动晋升。真实账本只做统计和预览，不修改正式记忆与待处理材料；现有 `memory.get` 审计行可照常写入。写入与撤销流程在隔离数据库或明确标记的测试材料上完成。功能完成后，用户可以在 Tauri 窗口逐批处理真实材料。

## 为什么先做这一项

2026-09-29 的只读快照：正式记忆 15 条；`proposed` 材料 137,493 条，分布在 1,779 个项目作用域；其中 62,268 条的 `scopeId` 含 `/` 或 `\`，不符合“项目 ID 是仓库名”的规则。`project:OneLedger` 自身有 68 条待处理材料和 1 条正式记忆。上述数字只是基线，实施时重新统计，不把它们写成运行时常量。

已有能力应复用：`scopeKind/scopeId` 及同一作用域整篇覆盖、`expectedRev`、采集指纹、FTS 检索、管理员侧蒸馏草稿与 `confirm_sources` 原子确认。当前 `distill.provider=none`，人工整理仍应走通。参考实现入口：

- `src-tauri/src/db.rs`、`store.rs`、`service.rs`、`distill_job.rs`、`http.rs`；
- `src/db/driver.ts`、`src/memory/store.ts`、`service.ts`、`distillJob.ts`、`src/http/app.ts`；
- `web/src/App.tsx`、`web/src/api.ts`。

已发现的具体缺口：管理台任务列表一次取回所有作用域与每作用域样本；材料明细默认只看全局前 200 条；任务审核提交会把 `task.sources` 的所有样本 ID 当成已审核来源，界面却只展示其中前 8 条；旧的路径型 `scopeId` 无可审查的归并入口。Rust 采集写入记忆后再登记指纹，指纹写入错误被忽略，需一并修好，避免处理过的来源重扫后重新入队。

## 本里程碑完成后的用户流程

1. 用户在 **Tauri 管理台**的蒸馏队列看到按项目、来源和待处理数量分页的列表，可筛出“项目归属待修正”的历史作用域；列表不把 WorkBuddy 来源自动称为“高信号”。
2. 点开一项历史作用域，可查看计数、来源分布和少量脱敏预览。管理员手动输入或选择确切的**仓库名**作为目标。软件展示预览：将移动的材料数、目标现有材料数、目标正式记忆 rev、受影响草稿、无法归并的原因。不能根据路径最后一段自动提交映射。
3. 管理员在预览仍有效时明确确认归并；成功后只有选定作用域中状态为 `proposed` 的材料改归目标项目，记忆正文和凭据不变化。操作可审计；尚未处理的移动材料可按操作记录撤销。
4. 在目标项目的材料页按来源、时间和状态筛选，逐页查看并**显式勾选**本次要处理的材料。默认不勾选；跨页选择数量始终可见。未展示、未选择的材料绝不因一次确认而离开队列。
5. 编辑器先载入该项目当前正式记忆的整篇正文和 rev；管理员基于选定材料合并修改，提交前看到“将处理的来源数”和正文差异。提交调用现有原子 `confirm_sources` / `confirmSources`，带 `expectedRev`。成功仅移除所选来源；版本冲突保留选择、正文和来源，供重新核对。
6. 如启用模型提供方，草稿生成也只接收管理员明确选中的安全材料，最多沿用现有单批 12 条、单条 4,000 字符、总计 24,000 字符限制；草稿须经审核才进入正式记忆。`provider=none` 时完整人工流程可用。

## 实施要求

### A. 后端查询与数据边界

- 为蒸馏任务提供**服务端分页和筛选**：项目名、归属异常、来源、待处理数量等摘要在 SQL 内聚合；返回本页数据和总数/下一页信息。不要把 1,779 个作用域及其样本全部传给前端，也不要每个作用域执行一次查询。每页建议 20～50 项。
- 为材料明细提供管理员鉴权的服务端项目/来源筛选与稳定分页；每页上限建议 50～100 条。大队列使用有确定次序的游标或经压测可接受的分页策略；任何接口都不能一次返回 13 万条正文。被拒收材料继续只给安全替换文本和规则类型。
- “归属异常”至少覆盖 `project` 作用域中包含路径分隔符、绝对路径/盘符迹象、`.` / `..` 片段的 `scopeId`。这只是待审标记，不能凭字符串自动推断真实仓库名。允许管理员查看原 ID 与候选仓库名；候选必须由可核实的来源信息支撑，最终仍需人工确认。
- Agent MCP 仍只见正式、安全的记忆；不得新增 inbox、草稿、凭据原值的 Agent 读取工具。管理台接口仍使用管理员权限，不能让 Agent Bearer 代替管理员密钥。

### B. 作用域归并、冲突和撤销

- 新增管理员专用的“预览 → 确认归并 → 条件撤销”服务操作和必要的 schema 迁移。预览返回来源作用域、明确目标仓库名、待移动数量与按来源分布、目标当前计数、正式记忆 rev、相关草稿状态，以及可用于提交时重校验的版本摘要。预览不得修改数据库或泄露 secret/PII 正文。
- 确认时在**单个事务**内重新验证预览摘要、目标 `scopeId` 是仓库名、来源/目标不同、所有待移动记录仍处于预期作用域与 `proposed` 状态；不一致返回冲突和新预览，不做部分归并。只更新已核实的 inbox 作用域，记录操作 ID、原/目标作用域、受影响来源 ID 和数量并写审计。正式记忆、已拒收材料、已保存凭据均不随之移动。
- 若来源或目标已有待审核草稿，确认归并前必须给出明确阻断或过期处理；不能让旧草稿随后把材料写回错误作用域。检查 `collect_fingerprints` 中同源记录：涉及记录时要在同一事务内安全处理归属与唯一键冲突，或给出可验证的保留策略，保证下次重扫不会因归并重复入队。
- 撤销只针对该操作实际移动的 ID；全部相关材料仍为 `proposed` 且仍在目标作用域时方可原子撤销。任一条已经蒸馏、删除或再次移动，则整体拒绝自动撤销并显示原因，不影响已写入正式记忆。不得以“把目标作用域全部改回去”的方式撤销。
- 归并和撤销接口应幂等或明确返回“已完成/已撤销”，不能重复写审计或重复移动。数据库写入失败必须整体回滚。迁移升级与备份/恢复需覆盖新表，旧库升级后数据保持原样。

### C. 蒸馏选择与采集可靠性

- 将任务页当前的 `task.sources.map(id)` 隐式提交改为**显式选择 ID**。编辑器至少能展示每条所选来源的 ID、来源、标题、时间及安全状态；选中的 ID 必须与提交给后端的 ID 一致。分页、筛选或刷新后，选中项不能被静默替换为别的来源。
- 后端在事务内继续复核每个来源是否存在、同一作用域、`proposed`、非 secret，标题和正文二次扫描通过、`expectedRev` 未变；任一失败保留正式记忆和全部来源。别只依赖前端按钮状态。
- 草稿生成接口改为接收并复核显式选中的来源 ID；保留现有安全扫描、长度上限、草稿过期与人工审核语义。未选中时禁止生成或确认。
- 修复 Rust `ingest_collected` 与 TypeScript 对应路径中的“记忆/队列写入”和“采集指纹登记”一致性。设计事务边界并传播指纹错误，不准用 `let _ = insert_fingerprint(...)` 吞错。验证指纹失败不会留下无法去重的新增材料；重扫已确认或已拒收的同一文件不会产生新队列或新拒收事件；内容变化恰好入队一个新版本。

### D. 管理台交互

- 在现有“蒸馏队列”内完成，不另起网页壳。提供可见的“归属待修正”筛选、预览与确认、可撤销的操作记录，以及项目材料的分页/勾选/正文差异和提交结果。
- 显示当前项目正式记忆 ID/rev、待处理数量、本次选中数量；确认前提醒“整篇覆盖”和“只处理所选来源”。归并或审核发生冲突时保留用户正在编辑的正文和选择，不能清空表单。
- 几万条材料的作用域不能把 Tauri 窗口卡死。列表请求、预览、确认都应显示进度/禁用重复提交；失败用明确错误说明，不能把失败渲染为成功。不要在管理台或审计中记录 Bearer、凭据原值、模型提示全文。

## 执行顺序与验证

1. **基线与保护。** 按 `AGENTS.md` 做改动前全量检查，至少 `npm run check`；记录当前活跃记忆、待处理量、异常作用域量、OneLedger 待处理量、现有配置与工作区未提交改动。只读查询，不打印材料正文或密钥。先准备隔离测试数据库，验证备份和旧库迁移；不得直接在用户正式库上跑迁移实验。窗口测试可用 `ONELEDGER_HOME` 指向独立测试目录，并为测试实例配置不同端口、关闭自动采集，避免碰到运行中的正式实例；结束后关闭自己启动的测试进程。
2. **数据和服务。** 先实现分页、归并预览/确认/撤销以及采集事务；补数据迁移和备份恢复，再接管理台。Rust Tauri 路径与 TypeScript 服务路径保持语义一致；若某接口只属于 Tauri 管理台，至少保证共用数据结构、备份和迁移兼容。
3. **窗口流程。** 接入 Tauri 管理台，使用隔离测试数据亲自走完“错误作用域 → 预览 → 确认 → 目标项目选择 → 编辑整篇 → 确认写入 → MCP `memory.get` 验证 → 条件撤销/冲突”。MCP 由 Agent 自己连接调用。验证真实账本时只读检查 OneLedger 的 68 条是否可全部分页访问；未经用户在产品窗口明确确认，不替用户自动处理这些真实材料。
4. **规模与故障。** 用不含真实秘密的合成库覆盖至少 140,000 条 inbox、1,800 个作用域、一个超大作用域、重名仓库、路径型作用域、跨页选择、并发队列变化、旧库升级、事务中途失败、重复请求、撤销后重做。记录查询和窗口响应耗时；消除全量前端加载与 N+1 查询。不要只以 68 条 OneLedger 材料验证性能。
5. **安全回归。** 管理员无权/Agent 密钥访问新接口应被拒绝；secret/pii、拒收材料、草稿仍不可经 Agent MCP 召回。检查归并后项目 ID 仍是仓库名、`global/personal` 语义不变、现有记忆 rev 不被归并操作推进。ZCode 新会话召回对 `project:OneLedger` 继续有效；至少再做 5 个无“记忆”提示的新任务核对启动召回，不把 ZCode 自带 Memory 算作 OneLedger 成功。
6. **质量门槛。** 改动后、启动前、提交前至少跑 `npm run check`；Rust 改动运行 `cargo test --offline --lib`。本机用打包的 Tauri 窗口验收；验证调试进程退出。Linux `check` 与 Windows `CI` 都需通过才能宣称可发版。任何失败先修复，再报告结果。若进入正式发版，严格按 `AGENTS.md` 同步六处版本号、`app_update.json`、Cargo.lock，并验证 exe 内嵌版本；没有完成发版检查时只交付代码和本地包，不打 tag、不宣称已发布。

## 验收门槛

- 项目任务和材料均由服务端分页；在合成大库及真实库只读测试中可打开和筛选，窗口不卡死，返回量受上限约束。报告冷/热请求的实际耗时与测试机器环境，不只写“性能良好”。
- 至少一个隔离样本完成归属预览、确认、审计、条件撤销；并发变化、重复提交、指纹冲突和注入的数据库失败均不产生部分移动。错误目标不能进入正式记忆作用域。
- 至少一个隔离项目含已有正式记忆和多条 inbox：只选择其中部分来源并编辑整篇，写入后 rev 恰好推进一次，只有选中的来源出队，未选中来源保留；MCP `memory.get` 读到新正文。过期 rev 返回冲突，原正文和来源保持不变。
- `provider=none` 的人工路径和有模型提供方的安全草稿路径都通过；草稿未审核时 MCP 不可见。模型测试可用本地受控 stub，不使用用户真实材料或真实模型账单。
- 当前用户正式库的存量行数和正式记忆在实施过程没有被自动迁移、删除或覆盖。提供真实库的只读预览结果，说明下一批可由用户在 Tauri 窗口处理的范围。
- 全量检查、Rust 测试、Tauri 窗口实测、Linux/Windows CI 结果均有可核对证据；未过项列明原因和影响，不以代码已写完代替完成。
